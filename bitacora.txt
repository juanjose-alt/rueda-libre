FUNCIONES DE HTML, CSS Y JAVASCRIPT

En el desarrollo del sitio web de Rueda Libre, cada tecnología
cumplirá una función específica.

HTML (HyperText Markup Language):
HTML se utilizará para crear la estructura y el contenido
de las páginas web. Permitirá organizar los títulos, párrafos,
imágenes, enlaces y formularios.

Ejemplo:
Crear una página que muestre el nombre de Rueda Libre,
una imagen de una bicicleta y una descripción de los servicios
de alquiler de bicicletas en Medellín.

2. CSS (Cascading Style Sheets):
CSS se utilizará para definir la apariencia visual del sitio web.
Permitirá establecer colores, tipos de letra, tamaños,
márgenes y la distribución de los elementos en la página.

Ejemplo:
Diseñar la página de Rueda Libre con colores relacionados
con la naturaleza, botones atractivos y un diseño adaptable
a celulares y computadores.

3. JavaScript:
JavaScript se utilizará para agregar interactividad y
comportamientos dinámicos al sitio web.

Ejemplo:
Crear una función que permita al usuario seleccionar el tipo
de bicicleta que desea alquilar y calcular el precio según
la cantidad de horas seleccionadas.

Conclusión:
HTML define la estructura y el contenido, CSS controla
la apariencia visual y JavaScript agrega interactividad.
La combinación de estas tres tecnologías permitirá crear
un sitio web funcional, atractivo y fácil de utilizar
para los clientes de Rueda Libre.

CORRECCIONES TÉCNICAS APLICADAS EN RESERVAS.HTML
--------------------------------------------------
1. Corrección de sintaxis en atributo `minlength`: 
   - Hallazgo: Se tenía escrito por error tipográfico `minlenght="3"` en el campo de nombre.
   - Corrección: Se ajustó al nombre de atributo estándar de HTML5 `minlength="3"`.

2. Actualización de validación por patrón (Regex) para Celular: 
   - Hallazgo: El patrón anterior permitía cualquier número de 6 a 10 dígitos sin restricción inicial.
   - Corrección: Se actualizó al patrón estricto `pattern="^3[0-9]{9}$"` para exigir exactamente 10 dígitos y que comience obligatoriamente por el número 3, según las reglas del negocio.

3. Coherencia en opciones de tipo radio: 
   - Hallazgo: El segundo botón de opción tenía valores cruzados ("montaña" vs texto de bicicleta eléctrica).
   - Corrección: Se estandarizó el `id="electrica"` y el `value="electrica"` para mantener concordancia absoluta con la etiqueta visible.

4. Cierre de etiquetas estructurales (`<select>`): 
   - Hallazgo: El menú desplegable del punto de recogida no tenía su respectiva etiqueta de cierre `</select>`, lo que alteraba la renderización del resto del formulario.
   - Corrección: Se incorporó el cierre correcto de la etiqueta y de sus opciones internas.

5. Corrección de sintaxis en el área de texto (`<textarea>`): 
   - Hallazgo: El atributo de longitud máxima estaba mal escrito y separado fuera de la etiqueta (`max length ="300"`).
   - Corrección: Se integró correctamente el atributo válido de HTML5 `maxlength="300"` dentro de la etiqueta de apertura del `<textarea>`.

6. Distribución visual por bloques (`<div>`): 
   - Hallazgo: Algunos elementos como el menú de selección y los términos y condiciones se alineaban horizontalmente por defecto.
   - Corrección: Se envolvieron de manera independiente en contenedores `<div>` para forzar un salto de línea vertical limpio y ordenado.

5. VERIFICACIÓN DE HERENCIA EN CSS (RETO 3)
--------------------------------------------------
- Propiedad que SÍ se hereda: 
  * `color` (o `font-family`). Verificado en DevTools (Computed) en los párrafos <p>, 
    los cuales heredan automáticamente el color Azul Noche (#14213D) y la fuente Open Sans 
    definidos previamente en el elemento padre <body>.
- Propiedad que NO se hereda: 
  * `margin` (o `background-color`). Verificado en DevTools (Computed), donde se observa 
    que los elementos hijos no heredan los márgenes ni el fondo del contenedor principal, 
    sino que manejan sus propios valores por defecto del navegador o reglas específicas.

    6. AUDITORÍA DE ESPECIFICIDAD Y CORRECCIÓN (MINI-RETO 10)
--------------------------------------------------
- Conflicto detectado: La regla `.activo` no aplicaba el color verde a la página actual.
- Análisis de especificidad en DevTools:
  * Selector `#menu a` -> 1 ID, 1 Elemento (Especificidad: 101).
  * Selector `.activo` -> 1 Clase (Especificidad: 10).
- Causa del problema: El selector `#menu a` tenía mayor especificidad (101) que la clase `.activo` 
(10), por lo que el navegador ignoraba la regla de la clase.
- Solución aplicada: Se corrigió combinando el ID, la etiqueta y la clase en un selector de mayor
 especificidad (`#menu a.activo`, puntuación 111) sin recurrir a `!important` ni a estilos en línea.
- Accesibilidad de enfoque: Se implementaron estados `:focus` y `:hover` claros con contornos visibles
 (outline) para garantizar la navegación por teclado con la tecla Tab cumpliendo con los contrastes
  WCAG.


Medición de box-sizing en DevTools
1. Sin box-sizing (Comportamiento por defecto / content-box)

    Qué ocurría: El ancho total de la tarjeta (.tarjeta-servicio) se calculaba sumando el ancho base especificado más el relleno (padding) y los bordes (border) por separado.

    Efecto: Esto provocaba que los elementos se expandieran más allá del contenedor deseado, alterando las dimensiones exactas y causando problemas de desbordamiento en el diseño responsivo.

2. Con box-sizing: border-box (Aplicado en el proyecto)

    Qué ocurre: Como se observa en la pestaña Computed de DevTools, al aplicar la regla global box-sizing: border-box, el navegador calcula las dimensiones totales incluyendo el relleno y los bordes hacia adentro de la caja.

    Resultado medido: El ancho total de la tarjeta de servicio se mantiene exacto, controlado y predecible, evitando que los espacios internos fuercen un crecimiento no deseado en la interfaz.
